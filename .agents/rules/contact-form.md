# [기술 스택 강제]

1. HTML: 시맨틱(Semantic) 마크업 & 완벽한 웹 접근성(A11y)
- **구조와 폼(Form)**: 화면 전체를 감싸는 `<main>` 안에 실제 데이터를 다루는 `<form>` 구조를 짜줘. 단순 `<div>` 남발을 피하고 `<fieldset>`, `<legend>` 등 폼 전용 태그를 활용해 줘.
- **웹 접근성(Accessibility) 최우선**: 모든 입력란(`<input>`, `<textarea>`)에는 반드시 짝꿍이 되는 `<label>`을 명시적으로 연결(`for`, `id` 속성 일치)해 줘.
- **스크린 리더 배려**: 에러 메시지는 `aria-describedby`로 연결하고, 폼 제출 성공 시 뜨는 토스트 메시지는 스크린 리더가 즉각 읽어줄 수 있도록 `aria-live="polite"` 속성을 부여해 줘. 키보드(Tab 키)만으로도 모든 입력과 제출이 가능해야 해.

2. CSS: Vanilla CSS (스타일 & 상태 변화)
- **레이아웃 (Form Layout)**: 'CSS Grid'나 'Flexbox'를 사용해 이름/성(First/Last name) 같은 항목이 모바일(Mobile-First)에서는 1단 세로 배치로, 데스크탑(`@media`)에서는 2단 가로 배치로 자연스럽게 정렬되도록 해줘.
- **상태 디자인 (States)**: 디자인 시안을 참고하여 모든 입력창과 버튼에 마우스를 올렸을 때(Hover)와 클릭/선택했을 때(Focus)의 상태를 시각적으로 뚜렷하게 구분해 줘.
- **에러/성공 테마**: `style-guide.md`에 있는 폰트와 색상들을 CSS 변수(`:root`)로 등록해. 특히 유효성 검사 실패 시(Red)와 성공 시(Green)의 포인트 색상을 일관성 있게 적용해 줘.

3. JavaScript: Vanilla JS (유효성 검사 & DOM 조작)
- **폼 유효성 검사 (Validation)**: 사용자가 '제출(Submit)' 버튼을 눌렀을 때, 필수 입력값이 비어있는지, 이메일 형식이 맞는지 정규식 등을 통해 꼼꼼하게 검사하는 로직을 짜줘.
- **에러 메시지 출력**: 조건에 맞지 않으면 브라우저의 기본 경고창(alert) 대신, 해당 입력칸 바로 아래에 예쁘게 디자인된 에러 텍스트를 띄우고 테두리를 붉게 만드는 CSS 에러 클래스를 토글해 줘.
- **성공 토스트(Toast) 팝업**: 모든 검사를 통과하면 성공 알림(Toast Message)을 화면에 띄우고, 몇 초 뒤에 부드럽게 사라지도록 만들어 줘.
